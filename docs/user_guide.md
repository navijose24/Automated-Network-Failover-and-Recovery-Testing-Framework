# User Guide & Experiment Execution Manual

## 1. Environment & Prerequisites

This framework executes real Linux kernel networking commands using **Linux Network Namespaces** (`ip netns`) and `iproute2`.

### Supported Environments
- **Ubuntu Linux (20.04, 22.04, 24.04 LTS)** natively.
- **Windows 11 with WSL2 (Ubuntu distribution)**.

### Resource Storage Policy
All project files and the Python virtual environment (`venv`) are maintained directly on the **D: drive (HDD / Data drive)**, preserving primary drive space:
- **Location**: `D:\git\Network Eng\s1\acn\project\Automated-Network-Failover-and-Recovery-Testing-Framework`
- **WSL Path**: `/mnt/d/git/Network Eng/s1/acn/project/Automated-Network-Failover-and-Recovery-Testing-Framework`

## 2. Launching the Web Dashboard

### Option A: From Windows (One-Click)
Double-click `run_dashboard.bat` or run from PowerShell:
```powershell
.\run_dashboard.bat
```
This automatically invokes Ubuntu WSL2 as root, activates the virtual environment, and starts the Flask server on port `5000`.

### Option B: From Linux / WSL Terminal
```bash
sudo ./run_dashboard.sh
```

### Accessing the Web Dashboard
Open your web browser and navigate to:
```
http://localhost:5000
```

## 3. Running the 6 Academic Experiments

### Experiment 1: Normal Network Operation
1. Navigate to the **Dashboard** (`/`).
2. Click **New Session**, name it `Exp1_Normal`, select `Experiment 1: Normal Network Operation`, and click **Start Experiment**.
3. Observe live ICMP telemetry on the line chart. Verify:
   - Packet Loss: `0.0%`
   - Active Path: `PRIMARY` (`veth_c_p`)
   - Latency: Sub-millisecond (~`0.03 - 0.05 ms`).
4. Click **End Session**. Final metrics are automatically computed and persisted.

### Experiment 2: Primary Link Failure
1. Click **New Session**, name it `Exp2_Link_Failure`, select `Experiment 2: Primary Link Failure`.
2. Go to **Simulation** (`/simulation`), locate **Scenario #1: Primary Link Disconnection**, set duration to `10 Seconds`, and click **Inject Primary Link Disconnection**.
3. Watch the dashboard:
   - After 3 consecutive missed probes (~`1.5s`), `FAILURE_DETECTED` is raised.
   - The Failover Controller replaces the routing table entry to metric 50 on `veth_c_b`.
   - The active path badge updates to **BACKUP**.
   - Probes resume with 0% loss through the backup path.
4. When the auto-recovery timer completes (or you click **Restore Network Health**), primary link is restored.
5. Click **End Session**.

### Experiment 3: Gateway Failure
1. Start session `Exp3_Gateway_Failure`.
2. On **Simulation**, select **Scenario #2: Primary Gateway Unavailability**.
3. Click **Inject Primary Gateway Unavailability**.
4. The primary router ceases packet forwarding (`sysctl net.ipv4.ip_forward=0`).
5. Threshold detection triggers automatic route cutover to the secondary gateway.
6. Click **Restore Network Health**, then **End Session**.

### Experiment 4: Primary Interface Failure
1. Start session `Exp4_Interface_Failure`.
2. On **Simulation**, trigger **Scenario #3: Primary Interface Shutdown** (`veth_p_s`).
3. Verify that despite the client-facing link appearing up, end-to-end probing detects the downstream interface break and failover activates.
4. Restore and end session.

### Experiment 5: Primary Path Restoration & Failback
1. Start session `Exp5_Restoration_Failback` with **Enable Automatic Failback** checked.
2. Inject a failure and allow failover to switch traffic to `BACKUP`.
3. Click **Restore Network Health**.
4. The Failback Controller monitors the primary link: after 3 consecutive successful health checks, it restores the primary route priority (`metric 100`).
5. Traffic automatically transitions back to **PRIMARY**.

### Experiment 6: Repeated Failure Testing
1. In the **Simulation** tab, trigger failure and restoration cycles consecutively.
2. Navigate to **Analysis** (`/analysis`) to view the multi-cycle comparative bar charts and statistical distributions generated by the Pandas analytics engine.

## 4. Running the Automated CLI Test Suite

You can execute all tests directly from terminal without opening the browser:

```bash
# In WSL / Linux:
./venv/bin/python tests/test_topology.py     # Stage 2: Topology test
./venv/bin/python tests/test_monitoring.py   # Stage 3: Monitoring test
./venv/bin/python tests/test_scenarios.py    # Stage 4: Scenarios test
./venv/bin/python tests/test_failover.py     # Stage 5: Failover & Failback test
./venv/bin/python tests/test_end_to_end.py   # Stage 10: Complete 6-experiment suite
```

## 5. Exporting Data and Reports

Navigate to **Reports** (`/reports`) to download:
1. **Master Dataset CSV**: All sessions, metrics, and recovery times.
2. **Session Telemetry CSV**: Raw packet-by-packet logs with millisecond timestamps and RTTs.
3. **Session Summary CSV**: Formal resilience metric breakdown for individual trials.
